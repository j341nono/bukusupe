### レビュー後の修正（2026-09-26・Claude へ再引き継ぎ後）

Codex の M2 後半〜M4 をレビューし、次を直した。check:ext は**修正前のコードで 7 件 NG** になることを
確かめてから直し、修正後に全件通ることを確認した。

- **H1：意味配置に切り替えた後も星が仮配置の位置に残っていた。** 読み込み直後と「再配置」の後、
  156 件すべてが配置座標から最大 101 ずれ、星雲・タイトルと星が食い違っていた（一度検索すると直る）。
  原因は `StarField.setStars` がばねの目標（`searchX/Y`）を移動*前*の位置で初期化し、
  ばねが毎コマ古い位置へ引き戻していたこと。目標を新しい配置の位置にし、配置の移動中（`moveT < 1`）は
  アニメーションだけが星を動かし、ばねの状態をその位置に合わせるようにした。
- **H2：サンプル⇄実ブックマークの切り替えで IndexedDB が混ざっていた。** DB が一つだったため、
  切り替えると相手の埋め込みを削除し、星座の `lastMembers` を空で上書き保存し、相手の平均ベクトルを
  使い回していた。DB をデータ源ごとに分け（`bukusupe-chrome` / `bukusupe-sample`）、
  平均ベクトルはデータ源と一緒に保存して違えば取り直す。更新中にデータ源が変わったらページを読み込み直す。
- **M3：ブックマークの更新処理が重なって走り得た。** 更新と「再配置」を 1 本の Promise の鎖に直列化した。
- **M4：check:ext に構造上必ず通る確認があった。** 意味のある確認に置き換え、Chrome のデータ源の経路を足した
  （4 章の一覧を参照）。
- 旧 DB 名 `bukusupe` は使わなくなった（中身は残るが読まない）。審査員の環境は新規なので移行はしていない。

### レビュー後の修正・2 回目（中・低の項目）

- **検索中のタイトルは、星が軌道に着いてから左右と重なりを決める。** `StarField.isSettling`
  （目標との差 0.02 超または速度 0.05 超の星がある、または配置の移動中）を、カメラの移動中と同じ扱いにした。
  以前は真上のまま検索語を打ち替えると、動き出す前の位置で判断してタイトルが内側に出たり重なったりした。
- **誕生の演出を、不透明度をなめらかにする処理の後に置いた。** 前にあると、まだ生まれていない星が
  目標の約 2 割まで引き上げられ、「一つずつ生まれる」演出が薄まっていた。
- **5 件未満の統合は、星団の数が SPEC の下限（12 件以上なら 3 個）を下回るところで止める。**
  以前は 12 件で 1 個に潰れていた。`LAYOUT_VERSION` を 3 に上げた（保存済みの配置は一度計算し直される）。
- 保存の演出が終わったとき、入力欄にフォーカスがあれば真上のままにする。
  星座を素早く続けて選んだときは、世代番号で最後に選んだものだけを有効にする（Esc・削除でも世代を進める）。
- ラベルの幅は、ページの font-family と CSS の字間（星団名 0.12em、星 0.02em）で測る。
- 左側に出した省略タイトルにマウスを乗せたら、右端（星の側）を固定して全文を左へ伸ばす。
- IndexedDB：版上げが古いタブに止められたら画面で知らせ（`onblocked`）、
  別のタブが新しい版で開こうとしたらこちらは閉じて読み込み直す（`onversionchange`）。
- `CLAUDE.md` と `AGENTS.md` を現状に合わせて書き直し、**同じ内容**にした。

### M2 で残した課題（M3 に入る前に判断が要るもの）

- **解決済み**：分野語を大分類に対応させ、命名には大分類だけを使う。「DTM」11 件は「音楽」になった。
  埋め込みに使う元の分野語は変えず、保存済みの星の座標も変えずに名前だけ更新する。
- 星団の粒度の**分割**規則（件数が中央値の 2 倍超かつ締まりが中央値未満）は、
  サンプルでは一度も発動していない。**統合**（5 件未満）だけが効いている。
- 「料理」「お金・ニュース」など寄せ集めの星団が残る。SPEC どおりの `k = round(sqrt(N/2))` の結果。

### M3 に入るときに使えるもの

- `meta.generality`（IndexedDB）に「誰とでも似ている度合い」を保存済み。
  検索で YouTube・X・Amazon のような汎用ブックマークが上位に来るのを抑えるのに使う。
  実測：`search("宇宙を感じたい")` の上位 10 件に YouTube・X・Amazon が混ざる。
- `meta.mean-vector` に平均ベクトル。**検索語の埋め込みにも同じ平均を引く**こと。
- `view.setTopDown(true/false)` がカメラの傾き⇄真上（約 0.6 秒）。入力欄のフォーカスに繋ぐだけでよい。
- `__bukusupe.search(text, topK)` は現在、文字一致と補正後の意味検索の統合順位を返す。

### M3 の結果

- 文字一致は入力ごとに即時、意味検索は 2 文字以上で 300ms の入力待ち後に Worker で計算する。
  検索語とブックマークの双方に保存済み平均ベクトルを引き、正規化してから比較する。
- `meta.generality` は標準化した値を保存する。検索では正の汎用度だけを
  `0.03 × 汎用度` として意味スコアから引く。負値まで引くと Kubernetes のように
  汎用度が極端に低い星を毎回上位へ押し上げたため。
- フォルダも記事の URL パスもない入口ページは意味スコアを 0.16 下げ、
  タイトルが 3 文字以下で URL パスも薄い場合はさらに 0.2 下げる。
  補正後の全件の z 値を 0〜0.89 に写し、文字一致との `max` を取る。
  タイトル完全一致は 1.0 で常に最上位。
- 係数 0 / 0.01 / 0.02 / 0.03 はサンプル 9 検索で期待分野が各 34/45 件。
  0.04 / 0.06 は 33/45 件。0.03 を採用した。宇宙検索の上位 10 件に
  YouTube・X・Amazon は入らず、9 検索の上位 5 件に 4 回以上出る星もなかった。
- 最大 21 件を 3 / 6 / 12 の軌道へ表示上だけ移す。元位置への光の線、無関係な星の減光、
  バネでの復帰、真上へのカメラ回転、クリックカード、Enter・上下・Esc を実装した。
- `docs/screens/search.png` は「宇宙を感じたい」の検索画面。
  9 検索の上位 5 件と期待分野の件数は `docs/screens/search-results.json` に保存する。

### M3 検索画面の仕上げ

- 検索語と各星団の保存済み中心ベクトルを比較し、星の属する星団との類似度の正の部分に
  **0.5** を掛けて意味スコアへ足す。9 語の上位 5 件の期待分野は合計 **34→39/45 件**で、
  悪化した語はない。係数 0.5 と 0.75 はともに 39 件、1.0 は 38 件だったため、
  小さい方の 0.5 を採用した。「パスタ」は 2→4 件。
  ただし料理の星でタイトルにパスタ料理名を含むのは「失敗しないカルボナーラの作り方」1 件だけ。
- 1 位の最終スコアの **85% 以上**の星だけを引き寄せる（最大 21 件、3 / 6 / 12 の軌道）。
  9 語の引き寄せ数は順に 12 / 12 / 11 / 15 / 10 / 20 / 13 / 19 / 9 件。
- 常時表示する光は、移動先の星から元の方向へ 40px 以下だけ伸び、先端が透明になる尾。
  元の位置までの線は選択中またはマウスを乗せた星にだけ出す。
  内側ほど星を大きく明るくし、タイトルも大きくする。タイトルはブラックホールから外への
  延長線上に置き、右側は左揃え、左側は右揃え。重なりは順位順に間引くため外側から消える。
  外側のタイトルは暗めで、マウスを乗せると明るくなる。
- `docs/screens/search.png` と `docs/screens/search-results.json` は仕上げ後の結果。

### ラベル移動のなめらかさ（M2・M3 共通）

- 通常画面と検索中のラベルを同じ方法で動かす。表示候補・左右・重なりは、カメラが
  止まってから約 150ms 後、または拡大率の段階が変わったときにだけ再判定する。
  移動中は表示中の集合と測定済みの幅・高さを保持する。
- 座標はカメラ更新後、WebGL 描画と同じフレームで `translate3d` に書く。
  この位置更新は DOM のレイアウト値を読まない。ラベルの入れ替わりは opacity の
  180ms の変化で見せる。
- `check:ext` は通常画面・検索中をそれぞれ約 0.75 秒ドラッグする。
  描画と位置更新は 84/84 コマ、89/89 コマで一致し、更新時間の最大は
  通常画面 0.10ms、検索中 0.40ms。
  Chrome の `LayoutCount` とラベル再判定回数はドラッグ中どちらも増えなかった。

### クリック操作・ブラックホール・視点の調整

- 表示中の星タイトルは通常画面・検索中ともクリックでき、星本体と同じカードを開く。
  星団名はブックマークを1件指さないためクリック対象にしない。
- ブラックホールの暗い中心の周囲に明るい細い輪と淡い光を置き、藍色の背景から識別しやすくした。
- 左ドラッグは従来どおり移動、右ドラッグの上下は視線の傾きだけを変える。
  真上から 0〜60 度に制限し、地図の方角は固定する。検索で真上へ移ったあとも、
  検索を終えると右ドラッグで決めた傾きに約 0.6 秒で戻る。

### 遠距離の星団名から拡大

- 遠距離の星団名だけをクリック対象にし、星団中心へ約 0.65 秒かけてカメラを移す。
  星団の半径と現在の視野角・傾きから、星団全体が見える距離を求めて拡大する。
  中・近距離の星団名にはこの操作を付けず、星のタイトルクリックは従来どおりカードを開く。
- 手動の移動・拡大縮小・傾き変更を始めたら、カメラの自動移動を中断する。
  `check:ext` は遠距離の「AI」をクリックし、中心への移動、拡大、星タイトルの表示を確認する。

### M4 星座

- 検索中の「星座にする」または Ctrl+Enter で編集する。引き寄せた上位 12 件を初期メンバーとし、
  星の本体・タイトルをクリックして加除する。明示的に加えた id は `pinned`、外した id は
  `excluded` に保存する。選んだ星には小さな輪を付ける。
- `Constellation` は SPEC 9 章の形のまま IndexedDB の `constellations` ストアに保存する。
  保存時には検索語の埋め込みも `queryVector` に保存する。DB は v2 に上げた。
- 線は保存済み地図座標を使ったプリム法の最小全域木。同距離なら id 順で割り、入力順序が
  変わっても辺が同じになる。星が 1 個以下なら線は作らない。
- 保存で星を元位置へ戻し、カメラを真上のままメンバー全体へ寄せる。約 0.95 秒後から辺を
  1 本約 120ms で伸ばし、全辺の後に名前を表示する。通常時は線を 15% で表示し、
  下の名前から呼び出すと 85% にして全体へ寄せる。再選択・Esc で解除する。
- 呼び出すたびに現在のブックマークで検索し直す。メンバーは
  `pinned ∪（引き寄せ対象の上位 12 件 − excluded）` とし、現存する id だけで線を作る。
  `lastMembers` は呼び出し後に更新する。ブックマークの削除通知・再読み込み時にも
  消えた id を `lastMembers` から取り除く。新星は見送り（0 章）。
- 呼び出し中に名前を変更したり星座だけを削除したりできる。
- `docs/screens/constellation-edit.png`、`constellation-drawing.png`、
  `constellation-saved.png` は「宇宙を感じたい」から「わたしの宇宙」を作った画面。
