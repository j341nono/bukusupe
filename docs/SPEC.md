# ブクスペ（Bookmark Space）仕様書

## 1. 目的と前提

- ハッカソン「HACK SONIC」（テーマ「宇宙をハックせよ」、2026年9月25日〜27日）向けの個人開発。残り時間は実質1日半。
- Chromeのブックマークを「星」として意味的に配置し、検索で星を引き寄せ、自分で選んだ星を線で結んで「星座」として保存・再表示するChrome拡張機能（Manifest V3）。
- 審査はChrome拡張機能としての配布で問題ないことを主催者に確認済み。審査員はリポジトリの完成済みフォルダ（またはzip）をデベロッパーモードで読み込む。ビルドは要求しない。
- 重視する審査軸：テーマへの愛、UX、技術的挑戦、独自性。

## 2. 物語（発表の軸）

人類は昔から、夜空の星に名前を付け、星座にまとめて、道を見つけてきた。ブックマークは、Webという宇宙の中で自分が名前を付けた星である。ブクスペでは、検索で集めた星を自分で選んで結び、名前を付けて「星座」にする。

- 本物の星座の星は、地球から同じ方向に見えるだけで、実際の距離はばらばら。ブクスペの星座も、意味の上では別々の星団にある星を「自分の目的」という視点で結んだもの。
- ブラックホール（検索）の引力は検索体験の比喩であり、実際の宇宙物理を再現しているとは主張しない。

見た目の意味は常に一貫させる。

| 見た目 | 意味 |
|---|---|
| 星 | ブックマーク1件 |
| 星団 | 意味の近いブックマークのまとまり |
| 星の明るさ | 最近使ったか（最終利用日時） |
| ブラックホール | いま探しているもの（検索語） |
| 星座 | 自分で選んで名前を付けた星のつながり（保存済み検索） |
| 新星 | 星座を呼び出したとき、前回の保存後に新たに加わる候補 |

## 3. 最初の30秒の体験

1. 拡張機能のアイコンを押すと、専用タブでブクスペが開く。初回はモデルの読み込みと埋め込み計算の間、「星が一つずつ生まれていく」演出で進み具合を見せる。
2. 斜めから見た銀河の円盤のように、星団と星が並ぶ。既存のブックマークフォルダが、最初の星座としてかすかに描かれている。意味で並べた地図の上では、一つのフォルダの星があちこちの星団に散らばっていることが見える。
3. 入力欄の下に検索候補が3つ出ている（大きな星団の名前など）。タップすると、画面中央にブラックホールが現れ、関連する星が同心円の軌道に引き寄せられる。
4. 「星座にする」を押すと、星が元の位置へ戻りながら線で結ばれ、名前が浮かび上がる。

## 4. 完成ライン（ここまでで審査可能）

優先順に：

1. アイコンから専用タブで開く
2. ブックマークの取得、ブラウザ内での埋め込み計算、意味配置（星団→星）
3. 一つの入力欄による文字一致＋意味検索
4. ブラックホールへの引き寄せ（同心円の軌道）
5. 星を選んで元のページを開く
6. 星座の保存と呼び出し（最小全域木での線、保存時の演出）

意味検索または星座がない状態は完成としない。

完成ライン後に順次：フォルダの自動星座 → 新星 → 明るさ（最終利用日時）→ 拡大率に応じた表示の細部 → ファビコン → 新しいタブへの割り当て → Web検索への導線。

審査用の版には入れない：ブックマークの削除（審査員の本物のブックマークを消す事故を防ぐため）、閲覧履歴（history権限）の利用。

## 5. 技術構成

- Chrome拡張機能 Manifest V3。TypeScript＋Vite。描画はthree.js。UIフレームワークは必須ではない（素のTSで可）。
- 権限：`bookmarks`、`storage`。必要なら `unlimitedStorage`。
- アイコンのクリック（`chrome.action.onClicked`）で `chrome.tabs.create({ url: chrome.runtime.getURL("index.html") })`。
- データの保存：埋め込みベクトル、配置、星座はIndexedDBに保存する（1件あたり384次元のfloat32）。
- 開発用に、`chrome.bookmarks` の代わりにサンプルデータ（100〜200件のJSON）を読み込むモードを用意する。通常のViteの開発サーバーで画面を確認できるようにし、デモのフォールバックにも使う。

## 6. 埋め込み（ブラウザ内で完結）

- モデル：`Xenova/multilingual-e5-small` の `onnx/model_quantized.onnx`（int8、約118MB。トークナイザー約17MBと合わせて約135MB）。実行はtransformers.jsのWebAssemblyバックエンド。WebGPUは使わない。
- 重みの重さの大半は25万語の語彙の埋め込み表で、計算量は小さい。GGUFは使わない。
- モデルの重みは初回起動時にHugging Faceから取得してキャッシュする（100MB超のためGitHubに通常の方法ではコミットできない）。
- Manifest V3の制約：
  - transformers.jsが実行時にCDNから読み込もうとするONNX Runtimeの補助ファイル（`.mjs` と `.wasm`）は拡張機能に同梱し、`env.backends.onnx.wasm.wasmPaths` を同梱先に向ける。必要なら `web_accessible_resources` に登録する。
  - manifestのCSP：`"extension_pages": "script-src 'self' 'wasm-unsafe-eval'; object-src 'self'"`
  - 外部から取得してよいのはモデルの重み（データ）だけ。プログラムは必ず同梱する。
- 計算は拡張機能ページから起動するWeb Workerで行い、UIを止めない。
- パイプライン：`feature-extraction`、`{ pooling: "mean", normalize: true }`。
- 接頭辞は必須：ブックマーク側は `passage: `、検索語は `query: `。
- ブックマーク側の入力文：
  `passage: {タイトル} | {フォルダの完全なパス} | {ドメイン} {URLのパスを記号で区切った単語}`
  - 例：`github.com/anthropics/claude-code` → `github anthropics claude code`
  - 上位100程度のドメインに分野の語を足す小さな辞書を用意する（例：`qiita.com` → `プログラミング 技術記事`）。
- 計算は初回の取り込み時と、ブックマークの追加・変更時（`chrome.bookmarks.onCreated` / `onChanged` / `onRemoved`）だけ。画面を開くたびに全件を再計算しない。

## 7. 配置（意味は平面に、奥行きは見た目だけ）

### 方針
- 星はすべて一枚の平面（z≈0）に置く。奥行きに意味を持たせない。
- 何もしていないときはカメラを約40度傾け、銀河の円盤のように見せる。入力を始めたら約0.6秒でカメラを真上に回し、読みやすい地図にする。
- 左ドラッグで移動、ホイールで拡大縮小、右ドラッグの上下で傾きのみ調整する。
  地図の方角は回転させない（場所の記憶を保つため）。傾きは真上から 0〜65 度。

### 手順（星団 → 星の二段構え）
1. **星団に分ける**：コサイン距離のk-means（k-means++、乱数の種は固定）。`k = clamp(round(sqrt(N/2)), 3, 20)`。Nが12未満なら1つの星団にする。
2. **星団の中心を置く**：各星団の平均ベクトルをPCAで2次元にし、適当に拡大する。そのうえで、星団を半径 `r = 間隔 × sqrt(件数) × 1.1` の円として、重ならないように押し広げる（単純な反発の反復で可）。
3. **星団の中の星を置く**：フェルマー螺旋（ひまわりの種の配置）。星団の平均ベクトルとのコサイン類似度が高い順に `i = 0, 1, 2, ...` とし、`r = s × sqrt(i + 0.5)`、`θ = i × 137.508°`。代表的な星ほど中心に来る。
4. **星団の名前**：メンバーに最も多いフォルダ名（30%以上を占める場合）、なければ最も多いドメイン、なければ「無名の星団 N」。すべてブラウザ内で決める。

### 安定性
- 星団の割り当てと座標は保存し、開くたびに再計算しない。
- 新しいブックマークは、平均ベクトルが最も近い星団の螺旋の次の位置（一番外側）に置く。他の星は動かさない。
- 削除されたブックマークの位置は空けたままでよい。
- 全体の再計算は「再配置」ボタンを押したときだけ。

### 拡大率に応じた表示
- 遠：星団の名前のみ。
- 中：各星団の代表の星（螺旋の内側3〜5個）のタイトル。
- 近：すべてのタイトル。
- タイトルはHTMLの重ね表示で描き、重要度の高い順に、重なるものを間引く。同時表示は60件程度を上限とする。

### 明るさ
- `BookmarkTreeNode.dateLastUsed`（Chrome 114以降）が新しいほど明るい。値がない場合は中間の明るさにし、「未使用」と断定しない。

## 8. 検索

- 入力欄は一つ。キーワードも文章も同じ欄で扱う。
- **文字一致**：1文字ごとに即時反映。タイトル・URL・フォルダ名に対する大文字小文字を区別しない部分一致。スコアの目安：タイトル完全一致 1.0、タイトル前方一致 0.9、タイトル部分一致 0.7、URL・フォルダ一致 0.5。
- **意味検索**：入力が2文字以上になり、打ち終わって約300ミリ秒後に実行。コサイン類似度の絶対値でしきい値を決めず、全件の中での順位（またはz値）で正規化する。
- **統合**：`スコア = max(文字一致, 意味検索の正規化値)`。タイトル完全一致は必ず最上位。
- **引き寄せる数**：上位21件まで（内側の円に3件、次に6件、外側に12件）。
- 検索時の星の移動は表示上の変位だけで、保存済みの座標は変えない。

### 引き寄せの見せ方
- ブラックホールは画面中央（平面上で画面中心に当たる点）に出す。
- 暗い中心の輪郭と淡い光で背景から識別できるようにする。
- 引き寄せた星は関連度順に同心円の軌道へ並べる。タイトルは外側へ放射状に表示する。
- 引き寄せた星から元の位置へ、細い光の線を残す（どの星団から来たかが分かる）。
- 関係のない星は暗くするだけで動かさない（不透明度25%程度）。
- 入力を消すと、星はバネのように元の位置へ戻る。

### キーボードと選択
- Enter：選択中の星（初期値は内側の円の1位）を開く。上下キー：候補を順に選ぶ。Esc：検索を消す。
- 星または表示中の星のタイトルをクリック（タップ）すると、タイトル・URL・フォルダと「開く」ボタンのカードを表示。PCでは星をダブルクリックしても開く。
- 入力欄の下に検索候補を3つ表示（大きな星団の名前など）。

## 9. 星座（中心機能）

### データ
```ts
type Constellation = {
  id: string;
  name: string;            // 初期値は検索語。書き換え可
  source: "search" | "folder";
  query?: string;          // source が search のとき
  queryVector?: number[];  // 検索語の埋め込み
  folderId?: string;       // source が folder のとき
  pinned: string[];        // 自分で加えた星
  excluded: string[];      // 自分で外した星
  lastMembers: string[];   // 前回表示したメンバー（新星の判定に使う）
  createdAt: number;
};
```

### 作る流れ
1. 検索中に「星座にする」を押すと編集状態になる。自動で入るのは引き寄せた上位の星（最大12個）。
2. 星をタップして加える・外すことができる（pinned / excluded に記録）。
3. 名前を入力（初期値は検索語）して保存。
4. 保存時の演出：星が同心円から元の位置へ戻りながら、最小全域木の辺が一本ずつ順に描かれ、最後に星座の名前が重心のあたりに浮かび上がる。

### 線の結び方
- 星の**元の位置（地図上の座標）**で、平面上の距離による最小全域木を作る（プリム法、星は十数個なので単純なループで可）。
- 平面上の距離の最小全域木は線が交差しない。同じ星なら毎回同じ形になる。

### 表示と呼び出し
- 保存した星座は、夜空にかすかな線（不透明度15%程度）として常に表示する。
- 画面下に星座の名前を並べる。選ぶと、その星座が明るくなり、カメラが全体の収まる位置へ移動する。
- 呼び出したときのメンバー＝`pinned ∪（現在の検索結果の上位 − excluded）`。検索はその時点のブックマークに対してやり直す。
- `lastMembers` に含まれず新たに加わった星は「新星」として光らせ、星座に残すか外すかを選べる。

### フォルダの自動星座（初回）
- 初回の取り込み時に、ブックマークが3件以上あるフォルダを星座として自動で作る（`source: "folder"`）。多すぎる場合は件数の多い順に8個まで。
- メンバーは、フォルダの平均ベクトルに意味が近い12件まで。
- 呼び出したときは、その時点のフォルダの中身から同じ規則で選び直す。

## 12. 既知のリスク

- MV3でのtransformers.jsの読み込み（CSP、補助ファイルの同梱）。M1で最初に潰す。
- 初回のモデル取得（約135MB）の待ち時間。進み具合の演出で体験に変える。
- タイトルに中身がないブックマーク（「ホーム」「Untitled」など）は意味検索が弱い。文字一致との統合と、入力文の拡張で補う。
- ブックマークが極端に少ない（20件未満）、または多い（数千件）審査員。少ない場合はサンプルデータへの切り替えボタン、多い場合は計算の進み具合表示で対応する。
