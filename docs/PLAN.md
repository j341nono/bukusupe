### 確認手順

**自動**（これだけで完了条件 1〜4 を通しで見られる）

```bash
npm run build && npm run check:ext
```

新しいプロファイルの Chrome に `dist/` を読み込み、専用ページを開いて次を確かめる。
最後に `OK` が出れば通っている（初回はモデル約 120MB を取得するので数十秒かかる）。

- 埋め込みが全件終わる／サンプル 150 件が読めている／`bookmarks` 権限がある
- 計算中も画面が動いている（コマ数を実測）
- **ONNX Runtime を拡張機能内から読んでいる**（`chrome-extension://…/ort/…` であること）
- **外部への通信がモデルの重みだけ**（`huggingface.co` と `us.aws.cdn.hf.co` 以外に出ない）
- 再読み込みで外部から取り直さない／エラー・警告が出ない

**手動**

1. `npm run dev` → `http://localhost:5173`
   HUD が「モデルを取り込んでいる 〜%」→「星を読み解いている n/150」→「意味を覚えた（150 件）」と進む。
   進んでいる間もドラッグで画面が動く。
2. 再読み込みすると、待たずに「意味を覚えた（150 件）」になる。
   DevTools → Application → IndexedDB → `bukusupe` → `embeddings` に 150 行あることを見る。
3. 意味検索の妥当性は、コンソールで確かめる。
   ```js
   await __bukusupe.search("確定申告", 3)
   // → 確定申告の手引き（国税庁） 0.873 / 個人事業主の開業届の出し方 0.847 …
   ```
4. 拡張機能として：`npm run build` → `chrome://extensions` → `dist/` を読み込む →
   アイコンを押す → 「データ源 Chrome」で自分のブックマークが同じ流れで進む。
   ブックマークを 1 件追加すると、その 1 件だけが計算し直される（HUD が一瞬 1/1 になる）。

### M1 で分かったこと（M2 以降に効く）

- transformers.js v4 は既定で ONNX Runtime を jsDelivr から読む。`configureOrt()` で同梱先に向け、
  `env.useWasmCache = false` で `blob:` URL 化も止めた。ここが MV3 の要点だった。
- multilingual-e5 は無関係な文どうしでも 0.78 前後の類似度が出る。短い汎用タイトル
  （「YouTube」「X」など）はどんな検索語でも上位に来る。**絶対値でしきい値を切らない**という
  SPEC 8 章の判断は正しい。M3 では順位（z 値）での正規化と文字一致との `max` を必ず入れる。

**2 時間で CSP・同梱が解決しない場合の退避**：埋め込みを使わず、
タイトル・フォルダ・ドメインの語彙による簡易ベクトル（hashing + TF-IDF 風）に差し替える。
配置と検索の形は変えずに済むよう、`Embedder` インターフェースで切っておく。

## M2 — 意味配置と描画（3 時間）

やること
- k-means（コサイン距離、k-means++、種固定、`k = clamp(round(sqrt(N/2)), 3, 20)`、N<12 は 1 星団）。
- 星団中心：平均ベクトルの PCA 2 次元 → 拡大 → 半径 `r = 間隔 × sqrt(件数) × 1.1` の円として反発で押し広げ。
- 星団内：フェルマー螺旋（`r = s × sqrt(i + 0.5)`、`θ = i × 137.508°`、平均ベクトルとの類似度順）。
- 星団名：最多フォルダ名（30% 以上）→ 最多ドメイン →「無名の星団 N」。
- カメラ：静止時 40 度傾き、入力開始で約 0.6 秒で真上へ。
- 拡大率による表示：遠＝星団名のみ、中＝代表 3〜5 個、近＝全部。HTML 重ね表示、同時 60 件上限。
- 配置と星団割り当てを IndexedDB に保存し、開くたびに再計算しない。「再配置」ボタンのみ全体再計算。

完了条件（画面で確認）— **2026-09-26 達成**
- [x] 意味の近いブックマークが同じ星団に集まっている（開発 / 料理・暮らし / 旅行 / ニュース が別の塊）。
- [x] 星団が重ならず、画面に収まっている（一番近い組で 1.88 の空き）。
- [x] 一つのフォルダの星が複数の星団に散っている（「あとで読む」は 5 つ、「AI」は 4 つの星団に分かれる）。
- [x] 引いた状態では星団名だけ、寄ると各星のタイトルが出る。ラベルは重なりを間引いて 60 件まで。
- [x] 再読み込みで同じ位置に星が出る（配置は IndexedDB に保存）。
- [x] 「再配置」を押したときだけ全体を計算し直す。

### 平均ベクトルを引く前処理

multilingual-e5 は無関係な文どうしでも 0.78 前後の類似度を返す（M1 で判明）。
全ブックマークの埋め込みの**平均を引いてから正規化し直したもの**を k-means と PCA に使う。
平均ベクトルは IndexedDB（`meta` の `mean-vector`）に保存し、後から増えたブックマークにも
同じ処理をかける。M3 の検索語にも同じ平均を使う。全体の取り直しは「再配置」のときだけ。

### 確認手順

```bash
npm run build && npm run check:ext
```

M1 の項目に加えて、次を自動で確かめる。

- 同じデータなら毎回まったく同じ座標になる（2 回計算して完全一致）
- 同じ星団の中で星どうしが重ならない（最小 3.09＝間隔の 1.55 倍）
- 星団どうしの円が重ならない
- 一つのフォルダの星が複数の星団に散っている
- ブックマークが 1 件増えても、既存の星の座標が 1 つも動かない
- 20 / 150 / 2000 件で配置が終わる（2000 件で 437 ミリ秒、描画 61 コマ/秒）
- 遠・中・近のスクリーンショットを `docs/screens/` に保存する

手動では、`npm run dev` で次を見る。

1. 引くと星団名だけ、寄るとタイトルが出る。ラベルが重なって読めない箇所がない。
2. ドラッグで移動、ホイールで拡大縮小。回転はできない。
3. 「再配置」を押すと並べ直る。押さなければ再読み込みしても同じ位置。
4. コンソールで `__bukusupe.setTopDown(true)` → 約 0.6 秒で真上に回る（M3 で入力欄と連動させる）。

### M2 で分かったこと

- 平均を引く前処理は効いた。引かないと全部が一つの塊に寄り、星団の差が出ない。
- 星団の粒度は均一ではない。「料理(31)」は料理・健康・お金・暮らしを飲み込み、
  「バックエンド(4)」は小さい。`k = round(sqrt(N/2))` の素直な結果で、SPEC どおり。
- 同じ名前の星団が 2 つ出ることがある（「AI」が 2 つ）。SPEC に規定はないので今は放置。

## M3 — 検索と引き寄せ（3 時間）

やること
- 入力欄 1 つ。文字一致は 1 文字ごと即時（タイトル完全 1.0 / 前方 0.9 / 部分 0.7 / URL・フォルダ 0.5）。
- 意味検索は 2 文字以上・打ち終わり 300ms 後。順位（または z 値）で正規化。
- 統合 `スコア = max(文字一致, 意味の正規化値)`。タイトル完全一致は必ず最上位。
- 上位 21 件を同心円（内 3 / 中 6 / 外 12）に引き寄せる。ブラックホールは画面中央。
- 引き寄せた星から元位置へ細い光の線。無関係な星は動かさず不透明度 25%。
- 入力を消すとバネで元の位置へ。保存座標は変えない。
- キーボード：Enter で開く、上下で選択、Esc で消す。クリックでカード、ダブルクリックで開く。

完了条件（画面で確認）
- [ ] 1 文字打った瞬間に文字一致の星が集まり始める。
- [ ] 「機械学習の記事」のような文章で、その語を含まない関連ブックマークが集まる（意味検索が効いている証拠）。
- [ ] 同心円が 3 / 6 / 12 に並び、タイトルが外向きに読める。
- [ ] 引き寄せた星から元の星団へ光の線が伸びている。
- [ ] Enter で 1 位のページが新しいタブで開く。上下キーで選択が移る。Esc で全部元に戻る。
- [ ] 検索を消して再読み込みしても座標が変わっていない。

## M4 — 星座（3 時間・完成ライン）

やること
- 検索中の「星座にする」→ 編集状態。上位 12 件を自動で入れる。タップで pinned / excluded。
- 名前（初期値は検索語）を付けて IndexedDB に保存（`Constellation` 型は SPEC 9 章のまま）。
- 保存の演出：同心円 → 元位置へ戻りながら、平面距離の最小全域木（プリム法）の辺を 1 本ずつ描き、
  最後に重心付近へ名前が浮かぶ。
- 保存済み星座は夜空に不透明度 15% で常時表示。画面下に名前を並べ、選ぶと明るくなりカメラが収まる位置へ。
- 呼び出し時のメンバー＝`pinned ∪（その時点の検索結果の上位 − excluded）`。

完了条件（画面で確認）
- [ ] 検索 → 「星座にする」→ 星を 1 つ足し 1 つ外す → 名前を付けて保存、が一度の流れでできる。
- [ ] 保存の演出で線が順に引かれ、名前が浮かび上がる。**線が交差していない。**
- [ ] 再読み込み後も星座がかすかに見えており、画面下の名前から呼び出せる。
